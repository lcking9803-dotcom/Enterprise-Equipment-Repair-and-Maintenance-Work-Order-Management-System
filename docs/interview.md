# 项目面试十问

## 1. 为什么采用单体而不是微服务？

四周版本业务边界有限，单体能降低部署和分布式事务复杂度。代码仍按认证、设备、工单、附件、看板分模块；只有出现独立扩缩容或团队边界时才考虑拆分。

## 2. 工单状态为什么不能由前端直接传？

前端不可信。后端为每个动作固定来源状态、目标状态和角色，避免从待受理直接跳到已关闭，也阻止重复派单。

## 3. 如何处理两个调度员同时派单？

工单表有 `version`。MyBatis-Plus 乐观锁把版本放进更新条件；只有一个请求更新成功，另一个影响0行并返回409，且不写审计日志。

## 4. 事务边界在哪里？

状态更新、业务字段更新和审计日志属于同一个事务。验收通过还会更新设备状态；任一步异常都回滚。

## 5. Redis 缓存什么？

缓存低频变化、重复读取的设备分类和看板聚合结果。工单/设备变更后主动失效。工单详情不缓存，避免权限和一致性复杂度。

## 6. JWT 和 RBAC 如何配合？

JWT 标识登录身份；每个请求仍从数据库加载用户是否启用及其角色。方法权限控制角色，Service 再校验工单归属和状态。

## 7. 为什么 MTTR 不统计未关闭工单？

开放工单尚无修复时间，强行用当前时间会改变指标口径。当前看板只统计已关闭工单，并单独展示开放数量。

## 8. 索引如何设计？

按真实查询组合建立状态+创建时间、维修人+状态、设备+创建时间、报修人+创建时间等联合索引，并通过 EXPLAIN 和5万条数据验证，而不是只凭字段感觉建索引。

## 9. 文件上传如何防护？

限制请求大小和 MIME 类型，存储键使用随机 UUID，不直接使用原文件名；下载前再次验证用户能否访问对应工单。生产环境还应增加内容检测和病毒扫描。

## 10. 如果部署后出现500怎么排查？

先用请求时间、接口和用户定位后端日志，再检查容器健康、数据库连接池、慢SQL、Redis/MinIO连接及磁盘。复现后补测试，再修复并回归。
